# Contributing

Thanks for helping make Codelit's public examples safer and easier to use.

1. Open an issue describing the outcome or defect before a large change.
2. Keep examples credential-free and read-only by default.
3. Add or update tests for behavior changes.
4. Run the repository's full verification command.
5. Open a focused pull request with the risk and verification evidence.

Generated examples are reviewed artifacts, not a place to add opaque prompts,
unbounded browser actions, or write-capable integrations without approval
gates.
